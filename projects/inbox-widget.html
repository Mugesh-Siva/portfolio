Inbox Priority
Widget

An AI-powered Gmail desktop widget that lives on your Windows wallpaper. It reads your inbox, classifies emails with an LLM, surfaces urgent items, detects deadlines, and drafts replies | without ever opening Gmail.

Overview

The Inbox Priority Widget is a Python desktop application built in August 2026 - completed in about a week. It uses the Gmail API (read-only OAuth2 scope) to pull emails every 90 seconds, classifies them using an OpenRouter AI model, and displays them as a floating, borderless glass panel on the Windows desktop | always behind other windows, like a Rainmeter widget.

The classification results are cached so repeated emails don't burn through API quota. When a free-tier rate limit is hit, the widget falls back to a secondary model automatically. The project is MIT licensed and open-source.

Key Features

→

Multi-account Gmail support: Connect multiple Google accounts. The widget polls all of them on a 90-second interval and merges results into a unified, priority-sorted inbox view.

→

AI classification: Each email is categorised as Urgent, Work, Personal, or Newsletter using an OpenRouter LLM. Categories are displayed with color-coded badges (red, blue, grey, collapsed).

→

Classification caching: Once an email is classified, the result is stored in a local cache keyed by message ID. Re-polling never re-classifies the same email, so free-tier API keys last significantly longer.

→

Automatic model fallback: If the primary OpenRouter model hits a rate limit, the widget silently falls back to a secondary model without user intervention or widget restart.

→

Daily AI brief: A 2-3 sentence summary generated at the top of the widget each day: "You have 3 urgent emails from David and HR. 2 high-priority tasks are due by Friday. Focus on Urgent and Work categories today."

→

Deadline detection: Detects time-bound language in email subjects and bodies | "by Friday", "EOD", "before Tuesday", "ASAP" | and displays deadline chips on those email rows.

→

AI draft replies: Click any email row to ask the AI to draft a reply. The draft appears in a text panel for review and copy-paste. The widget never sends emails automatically.

→

Windows 11 Mica/Acrylic glass: The widget window uses Windows 11's backdrop blur APIs via Tkinter + ctypes, giving it the same frosted-glass appearance as native Windows 11 panels.

→

Desktop-embedded: The window stays behind all other windows (HWND_BOTTOM), is draggable, resizable, and has a settings panel for quiet hours and display preferences.

Challenges & Solutions

Keeping the widget behind all windows on Windows 11
Used ctypes to call SetWindowPos(HWND_BOTTOM) after every focus event, since Windows may bring windows to the front on certain interactions. A background timer periodically re-sends the widget to the bottom of the Z-order.
API quota exhaustion on free-tier models
Classification caching means each unique email is only ever classified once. Even with 50 emails, the API might only see 5-10 new ones per poll cycle. Combined with the automatic fallback to a secondary model, the widget stays functional 24/7 on free keys.
Reliable OAuth2 token refresh without a web server
Used Google's google-auth-oauthlib InstalledAppFlow, which opens a local browser tab for the OAuth consent screen and spins up a temporary localhost server to catch the callback. Tokens are stored in a local file and refreshed silently on expiry.
