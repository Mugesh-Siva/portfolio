HotByte

A full-stack multi-restaurant food delivery application built as the final evaluation project for Hexaware's Java + React Full Stack Development training. Three distinct user roles, JWT + OAuth2 security, and a complete admin management panel.

Overview

HotByte is a full-featured food delivery platform built with React (Vite, JSX) on the frontend and Spring Boot on the backend, connected via a MySQL database. It was the final evaluation project for Hexaware's Java and React Full Stack Development training program, completed in July 2026.

The application supports three distinct roles | Customer, Restaurant Owner, and Admin | each with their own protected routes and dedicated dashboards. Authentication is handled through JWT tokens with an OAuth2 callback flow and a complete forgot-password mechanism.

Features by Role

→

Customer: Browse all restaurants and menu items with search, category filter (All/Burgers/Pizza/Indian…), veg/non-veg toggle, and sort options. Add to cart, manage quantities, proceed to checkout, and track orders in real time.

→

Restaurant Owner: Full restaurant dashboard: add/edit/remove menu items with multiple images, toggle item availability, view incoming orders by status (pending/preparing/ready/delivered), update order status in real time.

→

Admin: Complete management of all restaurants, menus, users, and orders from a dedicated admin panel. Approve or reject restaurant registrations, manage system-wide data.

→

Authentication: JWT-based login and registration, OAuth2 callback integration, forgot password with email-based reset, and a ProtectedRoute component enforcing role-based access on every route.

→

Cart & Checkout: Persistent cart context (CartContext), quantity management, delivery address input, order placement. Full checkout page with form validation.

→

UI & UX: Dark navy theme with orange accent (#ff6b35). React Toastify for all notifications. Item detail modal with image carousel. Responsive layout across all pages.

Challenges & Solutions

Role-based route protection at scale
A single ProtectedRoute component takes a requiredRole prop and wraps any route. AuthContext provides the user's role globally, keeping route protection consistent and eliminating repeated auth checks across pages.
Dynamic menu filtering without backend calls
All menu items, categories, and restaurants are fetched once on load with Promise.all(). All filtering (category, veg/non-veg, search, sort) is done client-side for instant UX with no additional API round trips.
OAuth2 callback handling
A dedicated /oauth2/callback route catches the redirect from the OAuth provider, extracts the token from query params, stores it in AuthContext, and redirects the user to the appropriate page based on their role.
