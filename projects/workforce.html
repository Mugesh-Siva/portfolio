Work Force

A gig economy platform connecting workers with recruiters for short-term and part-time opportunities. Real-time job listings, crew invite system, and role-based profiles. Published on Google Play Store in mid-2024.

Overview

Work Force is a React Native mobile application published on the Google Play Store in mid-2024. It addresses the friction in the informal gig economy | where workers and recruiters have no reliable, structured way to connect for short-duration opportunities like warehouse shifts, delivery driving, event staffing, or logistics work.

The app is built on Firebase | Auth for identity, Firestore for real-time data, Cloud Functions for server-side logic, Cloud Messaging for push notifications, and Storage for profile images. React Navigation handles the role-aware routing between Worker and Recruiter flows.

Key Features

→

Real-time gig listings: Recruiters post gig opportunities with title, category (Logistics/Tech/Driving), location, pay rate, and recruiter contact. Workers see listings update in real time via Firestore listeners.

→

One-tap enrollment: Workers apply for gigs with a single tap. Recruiters see all applicants and can confirm enrollments. The enrolled worker receives a push notification (FCM) with job details.

→

Crew invite system: Recruiters can invite specific workers to private gig opportunities. Workers receive invite notifications and can accept or decline from the app.

→

Role-based profiles: Worker profiles show skills, past gigs, ratings, and an availability toggle. Recruiter profiles show company name, active listings, and posted history. Role is set at registration.

→

Push notifications: Firebase Cloud Messaging delivers enrollment confirmations, crew invites, and listing updates. Handled by Cloud Functions triggered on Firestore document events.

→

Category filtering: Workers filter listings by All / Logistics / Tech / Driving. Filter state persists across navigation.

→

Bottom tab navigation: Home (listings), Jobs (enrolled/active), Profile, and Notifications | all built with React Navigation's bottom tab navigator.

Challenges & Solutions

Real-time listing updates on mobile without excessive battery drain
Firestore's onSnapshot listeners are attached only when the Home screen is focused (using React Navigation's useFocusEffect). When the user navigates away, the listener is unsubscribed. This prevents continuous background polling and reduces battery and bandwidth usage.
Server-side push notification logic without a backend
Firebase Cloud Functions (Node.js) trigger on Firestore writes | when an enrollment document is created, the function reads the worker's FCM token and sends a notification via the Firebase Admin SDK. No server to maintain.
Role-based navigation without exposing wrong screens
At login, the user's role is read from their Firestore profile document and stored in React Context. The root navigator renders either the Worker stack or Recruiter stack based on this role | so the wrong screens are never mounted, not just hidden.
